# WebUiLlm

Веб-интерфейс к локальному OpenAI-совместимому серверу: чат с моделью
в браузере, с учётными записями, сохранением переписки и потоковым ответом.

Фронт — React (Vite), обвязка — Flask: раздаёт собранный интерфейс и проксирует
запросы к модели, пряча за собой адрес бэкенда и CORS. Сами модели не
запускаются — нужен работающий сервер с `/v1/chat/completions`
(vLLM, llama.cpp, LM Studio, Ollama в OpenAI-режиме и подобные).

## Возможности

- **Вход обязателен.** Без учётной записи интерфейс показывает только форму
  входа, а бэкенд модели закрыт на сервере: прокси `/v1/*` тоже требует сессии.
- **Переписка хранится.** Чаты и реплики лежат в SQLite и переживают
  перезагрузку страницы; список чатов — слева, с переименованием (двойной
  щелчок) и удалением. Название чата берётся из первой реплики.
- **Чат с моделью.** Ответ приходит потоком; кнопка «Стоп» обрывает генерацию,
  недописанный ответ остаётся в переписке.
- **История диалога.** Переключатель «Помнить контекст» решает, видит ли модель
  предыдущие реплики этого чата.
- **Настройки генерации:** модель, температура, `top_p`, максимальная длина
  ответа, рассуждения, системный промпт. Пустые поля не отправляются —
  действуют значения самого бэкенда.
- **Глубина рассуждений** (`reasoning_effort`) при включённых рассуждениях.
  Уровни зависят от модели — каждая знает только свои: GLM-5.x — низкая /
  высокая / максимальная, Step и OpenAI-совместимые — низкая / средняя /
  высокая. Неизвестный модели уровень не отправляется.
- **Правка и перегенерация, как в AI Studio.** Любую реплику можно исправить
  прямо в ленте. У вопроса — «Сохранить и отправить»: всё после него
  отбрасывается, модель отвечает заново. У ответа — «Перегенерировать» и
  правка (модель увидит исправленный текст в следующих репликах).
- **Паспорт модели в шапке:** число параметров (у MoE — и активных), квант,
  размер весов; подробности — во всплывающей подсказке. llama.cpp сообщает их
  сам, для прочих бэкендов — по имени модели.
- **Markdown в ответах:** таблицы, списки, подсветка кода; рассуждения
  модели (`<think>`) — отдельным сворачиваемым блоком. Блоки кода длиннее
  12 строк сворачиваются до превью; у каждого — «Скачать» (расширение файла
  по языку) и «Копировать».
- **Скорость инференса.** Под ответом — скорость генерации в ток/с (живьём,
  пока модель пишет), скорость обработки промпта и токены запроса/ответа.
  Статистика хранится вместе с репликой и видна после перезагрузки.
- **Заполненность контекста.** Под полем ввода видно, сколько токенов даёт
  сервер на одну сессию и сколько из них уже занимает чат, — чтобы заметить,
  что диалог упирается в лимит. Ничего не ограничивается. Цифры точные на
  llama.cpp (`/slots`, `/apply-template`, `/tokenize`); на прочих бэкендах —
  из `usage` ответа, а где его нет, оценка со знаком «≈».
- **Несколько серверов моделей.** Список серверов берётся из реестра моделей
  (`LM_REGISTRY`) — он сам знает, что поднято и на каких портах, — или из
  `LM_BACKEND` через запятую. Модели всех серверов собираются в один список в
  настройках, у каждой — порт её сервера; молчащий сервер виден строкой «нет
  связи». Запрос уходит на тот сервер, где живёт выбранная модель; счётчик
  контекста и подсчёт токенов — тоже с него. Одна и та же модель на двух
  серверах — два независимых экземпляра, а не одна модель: в списке они
  различаются номером сервера («qwen #1», «qwen #2»), бэкенду уходит
  настоящее имя.
- **Распознавание речи.** Речевая модель (в списке — с 🎙) принимает
  аудиозапись: скрепка у поля ввода, любой формат — прокси сам приводит его к
  WAV 16 кГц моно через ffmpeg. Модели уходит только запись — без системного
  промпта, истории и текста рядом, как её учили. Расшифровка с таймкодами и
  говорящими приходит потоком: петли, оборванные сторожем сервера, стираются,
  таймкоды длинной записи пересчитываются от её начала (сервер режет её на
  окна по 90 с). Под ответом — длина записи и RTF. Расшифровка остаётся в
  чате, и её можно обсудить с обычной чат-моделью.
- **Светлая и тёмная темы**, выбор запоминается.

Адрес бэкенда и ключ к нему задаются на сервере и в браузер не попадают —
полей «Хост» и «API токен» в интерфейсе нет.

## Запуск

```bash
pip install -r requirements.txt
cd web && npm ci && npm run build      # один раз после клонирования
cd .. && python server.py
```

Откроется на `http://localhost:5900`. Первым делом зарегистрируйтесь — сервер
при старте печатает, сколько заведено учётных записей.

### Настройки

Скопируйте `.env.example` в `.env` рядом с `server.py` и поправьте под себя —
сервер читает его при старте и печатает, какие переменные оттуда подхватил.
Переменная, заданная снаружи, важнее файла:

```bash
PORT=5901 python server.py
```

| Переменная          | По умолчанию                 | Зачем                                        |
|---------------------|------------------------------|----------------------------------------------|
| `LM_REGISTRY`       | пусто                        | адрес реестра моделей, например `http://your-server:7000` |
| `LM_BACKEND`        | `http://127.0.0.1:8080` | адрес бэкенда; несколько — через запятую. С `LM_REGISTRY` — запасной список (по умолчанию пуст) |
| `LM_BACKEND_TOKEN`  | пусто                        | ключ к бэкенду, если он его требует          |
| `HOST` / `PORT`     | `0.0.0.0` / `5900`           | что слушать                                  |
| `ALLOW_REGISTRATION`| `1`                          | `0` закрывает регистрацию новых пользователей |
| `COOKIE_SECURE`     | `0`                          | `1`, если проект стоит за https              |
| `APP_DB_PATH`       | `webuillm.db`                | где держать учётки и переписку               |

Когда команда набрана, поставьте `ALLOW_REGISTRATION=0` — вход останется
работать, а посторонние завести себе учётку не смогут.

Реестр (`GET /` отдаёт `servers`: адрес, связь, `kind` — `asr` или `llm`,
`input`) опрашивается с тем же кэшем, что и серверы, — раз в 15 с. Не
ответил — остаётся прежний его список, а в интерфейсе строка «нет связи с
реестром»; не отвечал ни разу — берётся `LM_BACKEND`. Для серверов из
`LM_BACKEND` тип модели узнаётся по `/health`: ASR-сервер отдаёт там
`window_sec`.

### Разработка фронта

```bash
cd web && npm run dev      # :5173, горячая перезагрузка
```

Flask при этом должен быть запущен: dev-сервер Vite проксирует `/v1` и `/api`
на `localhost:5900`.

## Проверки

```bash
cd web && npm run smoke
```

Сквозной прогон: поднимает настоящий сервер на временной базе и поддельный
бэкенд модели, грузит собранный интерфейс в jsdom и проходит весь путь —
регистрация, отправка сообщения, рендер Markdown, счётчик контекста,
сохранение переписки, восстановление её после
перезагрузки страницы, несколько серверов и молчащий сервер, распознавание
записи (конвертация ffmpeg, окна, `discard`, сохранение расшифровки),
переименование и удаление чата, выход. Подменяются только сами модели.

## Как устроен вход

Сессия — случайный токен в httponly-куке; в базе от него лежит только хэш,
пароли — scrypt-хэшами (Werkzeug). Подряд идущие неудачные попытки входа
закрывают имя на пять минут. Ответ на неверный вход одинаков для
существующего и несуществующего имени — форма не превращается в проверку,
кто здесь зарегистрирован.

Чужой чат недоступен по прямому идентификатору: каждый запрос проверяет
владельца и отвечает 404.

## Пакетная обработка файлов

Отдельная страница `/local` — очередь транскрипции аудиофайлов из
`static/audio_package/<пакет>`: отсев тишины через ffmpeg, конвертация,
распознавание на бэкенде, `<F_ID>.txt` рядом с исходником и сводный
`<пакет>.xlsx`. Модель — заданная на странице, иначе первая речевая из общего
списка. Параметры распознавания — серверные умолчания, на которых мерили
качество; текст рядом с записью уходит, только если задан свой промпт.

ffmpeg не версионируется (~674 МБ): положите сборку в `ffmpeg/bin/`. Без него
проверка на тишину отключается.

Состояние очереди — в `local_state.db` (SQLite). Прежний `local_state.json`
переносится в базу при первом запуске и дальше не используется, оставаясь
резервной копией.

## Структура

```
server.py             Flask: раздача сборки, прокси /v1 и /api, чтение .env
auth.py               вход, регистрация, защита маршрутов
chats_api.py          чаты пользователя
backends.py           несколько серверов: какая модель где, маршрут запроса
llm_info.py           лимит контекста бэкенда и подсчёт токенов переписки
app_db.py             база приложения: учётки, сессии, чаты, сообщения
state_store.py        состояние очереди пакетной обработки
local_processing.py   конвейер пакетной обработки файлов
web/                  исходники интерфейса
  src/lib/            api.js (сеть и SSE), settings.js, useAuth.js
  src/components/     Sidebar, Composer, Message, Icons, тосты
  src/pages/          LoginPage, ChatPage, LocalPage
  smoke.e2e.mjs       сквозная проверка
static/dist/          сборка (не в репозитории — делается npm run build)
```

## API

| Путь                                    | Назначение                          |
|-----------------------------------------|-------------------------------------|
| `/api/auth/register` / `login` / `logout` / `me` | учётные записи             |
| `/api/chats`                            | список и создание чатов             |
| `/api/chats/<id>`                       | чтение, переименование, удаление    |
| `/api/chats/<id>/messages`              | дописать реплику                    |
| `/api/llm/limits`, `/api/llm/count`     | лимит контекста, подсчёт токенов    |
| `/v1/models`                            | модели всех серверов одним списком  |
| `/v1/*`, `/api/*`                       | прокси на сервер модели из `model` (после входа) |
| `/api/local/*`                          | очередь пакетной обработки          |

Все эти маршруты, кроме `/api/auth/*`, требуют действующей сессии.
